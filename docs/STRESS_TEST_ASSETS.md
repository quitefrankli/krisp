# Stress-test benchmark assets

The benchmark uses pinned copies of Khronos Flight Helmet and Intel Sponza. Asset files stay outside the repository. From the repository root, prepare the cache once with:

```sh
python3 applications/stress_test/benchmark_assets.py
```

The default cache is `build/benchmark-assets`, shared by Debug and Release builds. `stress_test run` automatically prepares it when the directory is missing, before starting workers or warm-up; `stress_test prepare-assets` performs the same preparation manually. Preparation downloads sources only when the cache is missing and local source inputs were not provided. It verifies each pinned SHA256, extracts only Sponza files referenced by the base GLTF, validates the models and textures, writes derived GLTF files, and atomically publishes an immutable cache with `prepared.json`. A valid current cache is reused. A damaged current cache or a cache prepared against an unknown lock is rejected rather than overwritten. Runs verify prepared-file checksums before launching workers and never download during measurement.

For offline preparation, place the exact Khronos source files under `SOURCE_DIR/FlightHelmet/` using the paths listed in `applications/stress_test/assets.lock.json`, and place the pinned Intel archive at `SOURCE_DIR/main_sponza.zip`. Pass `--source-directory SOURCE_DIR` to either `prepare-assets` or `run`; on `run`, this supplies sources for automatic preparation when the cache is missing. Local inputs receive the same checksum validation as downloads. ZIP paths are checked for traversal, duplicate entries, encryption, and symlinks before extraction.

Flight Helmet is pinned to KhronosGroup/glTF-Sample-Models commit `d7a3cc8e51d7c573771ae77a57f16b0662a905c6`, using its uncompressed PNG glTF variant. Its model README identifies the asset as donated by Microsoft and states that Microsoft waived copyright and related rights to the extent possible under law (CC0 1.0). The source README and all source model files are retained in the cache. Intel distributes Sponza Base Scene as `main_sponza.zip` under CC BY 4.0; its `credits_license.txt` and original archive are retained in the cache. The exact URLs, source revisions, license records, and hashes are in the lock file.

The material preparation recipe removes Flight Helmet ambient-occlusion bindings and makes only `LensesMat` opaque; if a pinned helmet revision carries `KHR_materials_transmission`, that transmission material extension and its declarations are removed as part of the same opaque-lens conversion. For Sponza only, the converter normalizes `light_bulb` emissiveFactor component 2 from the pinned source value `1.00000012` to `1.0`; it rejects any other source vector or out-of-range factor. The original archive and original GLTF remain unchanged in the cache. The converter fails on any other material extension, unsupported texture binding or sampler, non-triangle primitive, unsupported vertex attribute, or unexpected alpha material. Sponza contains unbound `TEXCOORD_1` attributes and white `COLOR_0` values; preparation verifies that every color component is exactly 1.0 and that every material samples UV set 0. These source attributes remain intact. A future source change that introduces non-white colors or binds another UV set fails preparation.

The `engine-pbr-opaque-bc3-v1` profile derives the runtime textures as BC3/DXT5 DDS files from the pinned source PNGs using the `krisp-benchmark-assets/3` converter. It converts all 87 images once during preparation, writes base-level-only DDS files, and points the derived glTF at `MSFT_texture_dds` sources marked both `used` and `required`; runtime files contain no PNG fallback. Original PNGs remain in the source cache. Texture dimensions, material bindings, and geometry are preserved. BC3 is lossy, including for normal maps, as explicitly approved for this benchmark profile. It uses one quarter of RGBA8 base-level texture storage; a DDS file can still be larger than its source PNG. The profile makes no loading-speed claim until measurements from the prepared assets are collected. `prepared.json` records the profile, converter version, and hashes of the exact derived files, so old PNG-profile baselines cannot be treated as compatible.

The converter uses Pillow 11.3.0 to read source PNGs; offline preparation of this profile requires installing `applications/stress_test/requirements-assets.txt` with `python3 -m pip install -r applications/stress_test/requirements-assets.txt`. This dependency is needed only when new derived assets must be prepared. A valid cache does not require Pillow.

When a recognized cache from the previous PNG profile is present, preparation verifies its cached source files and builds the new derived assets in a sibling staging directory. The previous cache remains in place until the complete new cache validates; publication retains a backup of the old cache. A missing cache follows normal preparation. A corrupt current cache fails closed, and an old cache with an unknown profile or converter is rejected rather than migrated.

`prepared.json` records the profile and converter version, pinned source identities and license hashes, source-to-derived material changes, per-file prepared SHA256 values, expected mesh/material/texture/renderable counts, and a resource-memory audit. Geometry memory uses the imported 48-byte textured vertex layout and 32-bit indices. Texture memory records actual BC3 base-level payload bytes and the single supplied mip level, alongside RGBA8 base-level and full-chain estimates for comparison; actual GPU allocation can vary by device. It also records the fixed Sponza camera views and the helmet import scale. These fields are part of benchmark asset compatibility and should be regenerated only when the pinned source or preparation recipe intentionally changes.

The approved preparation recipe also repairs 39 invalid source tangents parallel to their normals: 37 in `decals_1st_floor` and two in `lamps_2ndfloor_02`. Only the exact entries pinned in `assets.lock.json` change. The replacement projects the least-aligned positive coordinate axis onto the normal plane, normalizes it, rounds to float32, and preserves handedness. Positions, normals, indices, texture coordinates and original source images remain unchanged. The original source buffer is preserved separately. These pinned repairs are retained by converter version 3.
