# Stress-test benchmark assets

The benchmark uses pinned copies of Khronos Flight Helmet and Intel Sponza. Asset files stay outside the repository. From the repository root, prepare the cache once with:

```sh
python3 applications/stress_test/benchmark_assets.py
```

The default cache is `build/benchmark-assets`, shared by Debug and Release builds. `stress_test run` automatically prepares it when the directory is missing, before starting workers or warm-up; `stress_test prepare-assets` performs the same preparation manually. Preparation downloads sources only when the cache is missing and local source inputs were not provided. It verifies each pinned SHA256, extracts only Sponza files referenced by the base GLTF, validates the models and textures, writes derived GLTF files, and atomically publishes an immutable cache with `prepared.json`. A valid existing cache is reused. A damaged cache or a cache prepared against a different lock is rejected rather than overwritten. Runs verify prepared-file checksums before launching workers and never download during measurement.

For offline preparation, place the exact Khronos source files under `SOURCE_DIR/FlightHelmet/` using the paths listed in `applications/stress_test/assets.lock.json`, and place the pinned Intel archive at `SOURCE_DIR/main_sponza.zip`. Pass `--source-directory SOURCE_DIR` to either `prepare-assets` or `run`; on `run`, this supplies sources for automatic preparation when the cache is missing. Local inputs receive the same checksum validation as downloads. ZIP paths are checked for traversal, duplicate entries, encryption, and symlinks before extraction.

Flight Helmet is pinned to KhronosGroup/glTF-Sample-Models commit `d7a3cc8e51d7c573771ae77a57f16b0662a905c6`, using its uncompressed PNG glTF variant. Its model README identifies the asset as donated by Microsoft and states that Microsoft waived copyright and related rights to the extent possible under law (CC0 1.0). The source README and all source model files are retained in the cache. Intel distributes Sponza Base Scene as `main_sponza.zip` under CC BY 4.0; its `credits_license.txt` and original archive are retained in the cache. The exact URLs, source revisions, license records, and hashes are in the lock file.

The `engine-pbr-opaque-v1` profile preserves each asset’s mesh buffers and source textures. It removes Flight Helmet ambient-occlusion bindings and makes only `LensesMat` opaque; if a pinned helmet revision carries `KHR_materials_transmission`, that transmission material extension and its declarations are removed as part of the same opaque-lens conversion. For Sponza only, the converter normalizes `light_bulb` emissiveFactor component 2 from the pinned source value `1.00000012` to `1.0`; it rejects any other source vector or out-of-range factor. The original archive and original GLTF remain unchanged in the cache. The converter fails on any other material extension, unsupported texture binding or sampler, non-triangle primitive, unsupported vertex attribute, or unexpected alpha material. Sponza contains unbound `TEXCOORD_1` attributes and white `COLOR_0` values; preparation verifies that every color component is exactly 1.0 and that every material samples UV set 0. These source attributes remain intact. A future source change that introduces non-white colors or binds another UV set fails preparation.

`prepared.json` records the profile and converter version, pinned source identities and license hashes, source-to-derived material changes, per-file prepared SHA256 values, expected mesh/material/texture/renderable counts, and a resource-memory audit. Geometry memory uses the imported 48-byte textured vertex layout and 32-bit indices. Texture memory is reported as decoded RGBA8 base-level bytes and an estimate for a full mip chain; actual GPU allocation can vary by device and image format. It also records the fixed Sponza camera views and the helmet import scale. These fields are part of benchmark asset compatibility and should be regenerated only when the pinned source or preparation recipe intentionally changes.

The approved preparation recipe also repairs 39 invalid source tangents parallel to their normals: 37 in `decals_1st_floor` and two in `lamps_2ndfloor_02`. Only the exact entries pinned in `assets.lock.json` change. The replacement projects the least-aligned positive coordinate axis onto the normal plane, normalizes it, rounds to float32, and preserves handedness. Positions, normals, indices, texture coordinates and images remain unchanged. The original source buffer is preserved separately. Converter version 2 and new derived buffer hashes distinguish this preparation from earlier caches.
